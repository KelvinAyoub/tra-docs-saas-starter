# App Flow Document for TRA Compliance SaaS Starter

## Onboarding and Sign-In/Sign-Up
When a new user first visits the application, they land on a clean marketing page showcasing key features of the TRA compliance platform. A prominent “Get Started” or “Sign Up” button invites them to create an account. Clicking this button takes them to a registration page powered by Clerk, where they can sign up using their email and password or choose to use a social login provider such as Google or GitHub. During sign-up, the user is asked to confirm their email address via a verification link. After verifying, they are redirected to the main application and automatically signed in.

If the user already has an account, they can choose the “Sign In” option on the landing page and enter their credentials or authenticate via their linked social provider. Once authenticated, Clerk manages the session and redirects them to the main dashboard. In the event that a user forgets their password, a “Forgot Password” link on the sign-in page triggers a Clerk flow to send a password reset email. The user follows the email link, sets a new password, and is returned to the sign-in screen to access their account. At any point, a sign-out button is available in the application header, which ends the session and returns the user to the landing page.

## Main Dashboard or Home Page
Upon successful login, the user sees the global dashboard that serves as their central hub. A persistent sidebar on the left lists their businesses by name and includes an option to create a new business. The top header displays the user’s name, a notifications icon, and a profile menu where they can access settings or sign out. The main content area shows a welcome message and recent activity across all businesses, with quick links to resume a chat session, upload bank statements, or view the latest financial summary. An AI chat widget is anchored at the bottom right of the screen, ready to receive natural language input for adding transactions or asking for help.

From this dashboard, the user can click any business name in the sidebar to switch context. Selecting a business updates the content area to show that business’s specific dashboard, including balance overviews, recent transactions, and links to payroll, reports, and tax documents. Navigation between business dashboards and the global view is seamless, with the sidebar highlighting the current context and breadcrumbs in the header showing the path.

## Detailed Feature Flows and Page Transitions
When a user selects a business from the sidebar, they land on that business’s main page. Here, they can choose to start an AI chat by typing requests like “Add a TZS 50,000 fuel expense.” The chat component sends the message to the `/api/chat` endpoint, where the AI SDK interprets intent and calls Supabase to create the transaction. The response is streamed back and displayed in the chat window, confirming the addition.

To upload bank statements, the user navigates via the sidebar to the “Statements” page under the chosen business. They click an upload button, select a CSV or PDF file, and see a progress indicator while the document is parsed. Once parsing completes, the user is shown a list of extracted transactions to review, edit if needed, and then confirm. Confirmed entries are stored securely in Supabase under the current business context.

For payroll management, the user visits the “Payroll” page in the business’s section. They can add or edit employee details using a form that validates fields such as salary and tax thresholds. Upon saving, the system applies TRA logic in the `tra` library to calculate PAYE and SDL. The results appear in a pay run preview, and the user can finalize the payroll, triggering a PDF generation process that outputs official forms.

To generate tax reports, the user navigates to the “Reports” page. They select the report type—such as VAT or annual returns—and specify a date range. The system gathers relevant transactions, runs calculations server-side using the TRA logic, and displays a preview of the report. A “Download PDF” button lets the user receive a formatted document, created via a headless rendering service.

Administrators or users on higher subscription tiers can access an “Admin” panel from the profile menu. In this section, they manage user roles for each business, invite team members by email, and configure feature access. All transitions here maintain the business context, and once changes are saved, the user is redirected back to the relevant settings or dashboard page.

## Settings and Account Management
The profile menu provides an entry to personal account settings, where the user can update their name, email, and password. A separate tab within settings covers notification preferences, allowing the user to toggle email alerts for new transactions, payroll reminders, or system updates. Billing and subscription management appear in their own settings section. Here, the user sees the current plan, next billing date, and an option to upgrade or cancel. Integrations with Stripe handle payment details, and users can enter or update credit card information securely.

Business-specific settings are accessed by clicking a gear icon next to each business name in the sidebar. In this area, the user can rename the business, set its local currency and tax region, and configure bank account connections. After making changes, the user clicks “Save,” and the application returns to the business dashboard, reflecting the updated settings.

## Error States and Alternate Paths
If the user enters invalid data—such as an unsupported file format during statement upload or malformed transaction details in chat—the application displays a clear inline error message. The user can correct the data and retry the action. In cases of lost connectivity, a banner appears at the top of the screen indicating offline status; the user can continue working on local edits, which synchronize when the connection returns.

When a user attempts to access a business they do not belong to, the system enforces RLS policies and redirects them to an access-denied page with a message explaining the restriction. If an AI chat request fails due to parsing errors or API timeouts, the chat window shows a polite error and suggests rephrasing or trying again later. Any unexpected server errors trigger a global error boundary that logs details for the developer and shows the user a friendly prompt to refresh or contact support.

## Conclusion and Overall App Journey
From discovering the landing page to achieving daily tasks, the user’s journey is smooth and intuitive. They begin by signing up or logging in via Clerk, quickly add or switch among businesses, and use the AI chat or file uploads to record financial data with minimal manual effort. Payroll and tax report features guide them through complex calculations and document generation, while settings and subscription management offer full control over their account and billing. Robust error handling and clear navigation ensure that whether entering new expenses, managing teams, or reviewing compliance documents, the user can complete every step with confidence and clarity.
